# Competitor research

Reviewed primary product documentation on 28 November 2026. The findings describe documented interactions. They do not establish plan availability, task completion times, comparative usability scores or hands-on behaviour in logged-in competitor accounts.

| Product | Navigation, scheduling and editing | People, timesheets and mobile | Butterbox implication |
| --- | --- | --- | --- |
| Deputy | Schedule is a primary destination. Teams or open shifts can be placed on the grid. Keyboard shortcuts cover common actions. Copying and publishing are separate, with availability checks when a week is copied. | Location manager scope is explicit. Timesheet bulk approval respects selection and filters. Mobile managers can switch views and act on open shifts. | Provide direct grid entry, equivalent keyboard navigation and a publish preview. Apply approval to a clearly described selection. [Scheduling](https://help.deputy.com/hc/en-au/articles/4688731978639-Creating-shifts-on-your-schedule) · [Keyboard](https://help.deputy.com/hc/en-au/articles/4688878025487-Keyboard-shortcuts-when-scheduling) · [Timesheets](https://help.deputy.com/hc/en-au/articles/6997348381327-Approving-your-team-s-timesheets) · [Mobile managers](https://help.deputy.com/hc/en-au/articles/4753103029263-Manager-guide-to-the-Deputy-mobile-app) |
| When I Work | Scheduler has documented user views, cell editing, drag reassignment and modifier-drag copy. Copy-week offers conflict options. Employees see shifts after publishing. | Positions express duties or skills and relate to schedules and timesheets. Mobile supports creating, copying and publishing shifts with distinct save choices. | Separate Save draft and Publish. Give copy and move separate commands with explicit conflict outcomes. [Scheduler](https://help.wheniwork.com/articles/scheduler-reference-guide-computer/) · [Copy week](https://help.wheniwork.com/articles/copying-shifts-and-schedules-computer/) · [Positions](https://help.wheniwork.com/articles/creating-and-managing-positions-computer/) · [Mobile copy](https://help.wheniwork.com/articles/copying-shifts-ios/) |

Put correction beside the recorded time and show whom publishing affects. ## Component candidates

Start with existing React 19, Tailwind, Lucide, product tokens, server actions and the roster's existing quick-change logic. Extract and test shared presentation primitives without moving permissions or time calculations to the browser.

| Candidate | What it could replace | Trade-off and decision gate |
| --- | --- | --- |
| Existing roster grid + React Aria Components for Dialog and selected form primitives | New drawer focus, keyboard and announcement work. Preserve roster semantics and server results. | First choice for the vertical slice. Check dependency size, focus restoration, portals, touch alternatives and forced-colour behaviour in the actual Next.js build. Keep semantic HTML tables for read-only data unless grid navigation is required. [React Aria Dialog](https://react-spectrum.adobe.com/react-aria/Dialog.html) · [React Aria Table](https://react-spectrum.adobe.com/react-aria/Table.html) |
| DayPilot Lite | Resource timeline, snap, drag, resizing and virtualization. | Apache-2.0 Lite is a credible spike. Verify keyboard operation, screen-reader labelling, Perth/Sydney daylight boundaries, split-department lanes, conflict veto and a non-drag equivalent before investing. Compare Lite/Pro feature boundaries. [React Scheduler](https://doc.daypilot.org/scheduler/react/) |
| FullCalendar Premium | Resource timeline and time-grid rendering with resize and drop callbacks. | Resource timeline is Premium. Evaluate licence and interactive accessibility before procurement. A rendering adapter must leave permission, server validation, draft state and audit outside the library. [Timeline](https://fullcalendar.io/docs/timeline-view) · [Premium](https://fullcalendar.io/docs/premium) |

Avoid committing to a calendar replacement before a time-boxed comparison using the same Butterbox fixtures, both a 14-person venue and a large synthetic venue, keyboard-only interaction, mobile day agenda and a rejected change that preserves selection and scroll.
