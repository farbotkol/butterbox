## Proposed automated UX acceptance for delivery

Use existing isolated Playwright and DB tests. The delivery controller can consume the resulting exact-head CI and independent outcome evidence using its existing gate. These are proposed criteria for future stories and require no controller changes.

| Criterion | Observable pass condition |
| --- | --- |
| UX-C1 Add/edit | Owner and an allowed scoped manager can enter the editor from the desired roster cell, set a valid draft and see the correct team member and date without a route transition. One save writes one approved draft. Employee and different-scope manager see no write affordance and the server denies the mutation. |
| UX-C2 Move vs duplicate | Keyboard action and pointer each reach the same result. Move preserves the ID. Duplicate creates exactly one new draft. An overlap block leaves both original and destination unchanged. Warn mode announces the reason with an explicit proceed action where policy allows. |
| UX-C3 Scope and context | Capture venue, week, department, lens, scroll and focussed cell before a save. Verify they survive validation, rejected stale state and successful change. A tenant switch drops previous tenant state. |
| UX-C4 Publish | Publish preview reports exact changed subset, affected audience and blocking reasons. Cancel has zero writes. A permitted confirmation applies exactly the previewed selection. An employee sees only published shifts. Repeat submission is idempotent or safely rejected. |
| UX-C5 Details | User can open Employment from the person profile with no full-page transition, save once and see the persisted change. Other sections stay untouched. Invalid values and partial failure identify the affected section and preserve valid input. |
| UX-C6 Time | Manager sees original and corrected values side by side. The displayed approval target matches stored scope. Correction appends history. Lock, finalise and export obey explicit permission, period state and attribution. A request outside scope is denied. |
| UX-C7 Mobile and AA | At 1440×1000, 820×1180, 390×844 and 320 px reflow, key actions remain usable without document overflow. A named region may scroll independently for wide data. Verify focus order, modal return, non-drag alternatives, names, target spacing and critical colour contrast, plus axe core scans. |
| UX-C8 Recovery | Network failure or stale version preserves context and form values, announces the issue and permits a safe retry. A second attempt cannot create duplicate work. Screenshot and accessibility findings include route, role, viewport, result and exact head. |

Require behavioural evidence for the risky states affected by each change. Existing tests can prove several criteria. Screenshots support human review, and measured workflows plus server-state assertions establish the outcome.
